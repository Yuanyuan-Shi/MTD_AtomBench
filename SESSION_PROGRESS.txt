1. WHAT THE PROJECT DOES
Offline multi-teacher distillation (MTD) for the pi0.5 VLA (OpenPI, PyTorch) on ATOM-Bench FrankaPanda
(HF dataset AtomBench/FrankaPanda @ 4c2d4ed5…). No simulator, no rollouts, no success rates.
  Stage A (from pi0.5 base + LoRA): teacher_i1 (task i1 only), teacher_i5 (task i5 only), joint_bc (both).
  Stage B (from joint_bc; frozen teachers routed per sample by task): output_mtd, output_repr_mtd,
    output_repr_temp_mtd (each adds one KD term: flow output, normalized hidden states, temporal residual).
  Evaluation: held-out test pairs; all 6 models (teachers on their own task only, no KD metrics).
  x1 (composition task) has no released trajectories: reported "unavailable", never trained on.
Scale on AWS: batch 64 observations (32 pairs), Stage A 10 epochs over valid pairs
  (T1 11,309 / T2 17,430 / Joint BC 28,739 updates), Stage B 5,000 updates each, one seed (7).

3. CORE DESIGN (invariants — keep them when changing code)
  - Config = experiment + "hardware". hardware (launcher, nodes, gpus_per_node, output_root,
    frame_cache_dir, workers, max_train_obs_per_gpu, resume_interval, step_seconds, benchmark_file)
    is excluded from config_hash / matches_run_config: moving hardware never invalidates runs.
    Changing any experiment key does (finished runs then raise "stale"). tests/test_scaleup.py
    enforces local.json vs aws.json differ only in hardware + batch_size.
  - No experiment values as literals or default args in code; descriptive names (user preference).
  - Seeds: training_seeds (per replicate: LoRA init, batches, per-step tau/noise via
    seed*STEP_SEED_STRIDE+step) and data_seed (global: per-task split default_rng([data_seed, task]),
    eval = data_seed+1, probes +2, audit +3). splits.json records data_seed + split scheme; data.py
    refuses a mismatching splits.json.
  - Pairs: (t, t + execution_horizon) consecutive policy queries (config, default 1); both 50-step
    chunks fully inside the episode; batch rows interleaved [p0_t, p0_t+k, p1_t, …] — the temporal
    loss reshapes (-1, 2, …) on this order.
  - GPU-count invariance: global batch / tau / noise drawn from (seed, step) and sliced per rank;
    augmentation drawn per rank. Logged losses are all-reduced means. Rank 0 owns all files/W&B.
  - compare(): augment once, same tau/noise/observation for student and teacher (asserted).
  - Language KD mask = instruction + discretized-state tokens (all real tokens except BOS and the
    "\nAction: " cue).
  - Angles rx, ry, rz (angle_dims 11–13): wrapped into (center-pi, center+pi], center = train circular
    mean snapped to pi/2 (rx = pi, ry = rz = 0), recorded in splits.json. Fixes i5 episodes 50/66 storing
    roll as -pi (was normalized to ~-26 and caused 30x loss spikes). Pose = Panda flange xyz [m] in base
    frame; rx,ry,rz roll-pitch-yaw [rad], R = Rz·Ry·Rx (verified via forward kinematics).
    data.to_physical_actions() denormalizes (optional output_angle_center=0 for (-pi, pi] robots).
  - Frame cache: all frames decoded once into 224x224 uint8 .npy memmaps (~57 GB) using exactly the
    training path (LeRobot pyav decode, uint8 conversion, openpi_client PIL resize_with_pad).
    Bit-identical to video decoding (test). Without it a batch takes 13–16 s; with it ~4.5 s/step locally.
  - Stage-A gate: a model is "trusted" only if fixed train AND validation probe losses decrease;
    Stage B refuses untrusted Stage A. Stage-B variants must share one joint_bc init hash.
  - result.json / evaluation.json are written last = completion markers; reruns skip finished jobs.
    Resume checkpoints every hardware.resume_interval steps (newest only), deleted after success.

5. AWS RUNBOOK (SLURM, 3 nodes x 8 H100, shared filesystem)
  a) git clone https://github.com/Yuanyuan-Shi/MTD_AtomBench.git && cd MTD_AtomBench
     bash setup.sh                         # needs git + uv; re-runnable
     source atom_mtd_offlinedata/env.sh
     "$ATOM_PYTHON" -m atom_mtd_offlinedata.prepare --config atom_mtd_offlinedata/configs/aws.json
     git status                            # splits.json / norm_stats.json must be UNCHANGED
     "$ATOM_PYTHON" -m pytest -q atom_mtd_offlinedata/tests
  b) Check hardware.frame_cache_dir (/opt/dlami/nvme/atom_frame_cache) exists and is writable on every
     node (local NVMe, ~57 GB free); edit it in aws.json if not (hardware key: safe to change).
  c) W&B is online-only and required: Forge gateway https://forge.coreweave.com/api/wandb, project
     atom-mtd-offlinedata. Provide WANDB_API_KEY (or ~/.netrc entry for api.wandb.ai) to the job.
  d) "$ATOM_PYTHON" -m atom_mtd_offlinedata.run_experiment --config atom_mtd_offlinedata/configs/aws.json \
       --phase main --dry-run              # prints plan (Option B) and all srun/torchrun commands
  e) Recommended test order (submit from repo root):
     1. 1-node smoke first: copy aws.json OUTSIDE git with hardware.nodes=1 and
        hardware.output_root=atom_mtd_offlinedata/runs/aws_1node (else step 2 would skip its finished
        jobs), then CONFIG=/path/copy.json PHASE=smoke sbatch --nodes=1 \
          atom_mtd_offlinedata/launch/slurm_experiment.sbatch
        Exercises DDP on 8 GPUs, the cache build and sharded evaluation.
     2. 3-node smoke: PHASE=smoke sbatch atom_mtd_offlinedata/launch/slurm_experiment.sbatch
        (exercises 16-GPU multi-node jobs). Writes runs/aws/smoke_passed.json (required by main).
     3. Optional: MODE=benchmark sbatch … -> reports/benchmark_aws.json; plan.py then uses measured s/step.
     4. Main: sbatch atom_mtd_offlinedata/launch/slurm_experiment.sbatch (est. ~13 h with placeholder
        timings; Stage A ~9.8 h: T1 then Joint BC on 16 GPUs, T2 on 8; Stage B one variant per node).
  f) Outputs: runs/aws/<smoke|main>/<variant>_seed7/ (config.json, metrics.jsonl, result.json,
     evaluation.json, checkpoint/), job logs runs/aws/<phase>/logs/<variant>_<kind>.log, plan.json,
     comparison.{json,md}; SLURM log atom_mtd_offlinedata/reports/slurm-<name>-<id>.out.
     Resubmitting the same sbatch skips finished jobs and resumes interrupted ones.

6. LIKELY FAILURE POINTS TO CHECK FIRST
  - srun steps: launcher uses `srun --overlap --gpus-per-node=8` and narrows GPUs via ATOM_GPU_IDS ->
    CUDA_VISIBLE_DEVICES inside the step (launch/__init__.py). Cluster gres/cgroup policy may differ.
  - Multi-node torchrun rendezvous: c10d on the job's first host, port 29500 + job index; EFA/NCCL env
    vars may be needed for speed (planner assumes internode_efficiency 0.85).
  - DDP: find_unused_parameters=True, static_graph for >= 8 GPUs (upstream train_pytorch.py); rank 0
    runs probes while other ranks wait in NCCL (default timeout should suffice with the frame cache).
  - Memory: <= 16 observations per GPU (max_train_obs_per_gpu); Stage B holds student + 2 bf16 teachers.
  - preflight (run by run_experiment) needs CUDA, data, base checkpoint SHA, and a W&B round trip.
  - If a Stage-A model is untrusted (probes did not decrease) the pipeline stops by design.
